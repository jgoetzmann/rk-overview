The problem is quantization, not coefficient prettinessheld up

Original: In floating point, h·b constant-folds and 1/3 costs the same as 0.25; the premise only survives in fixed point on an FPU-less MCU, where a power-of-two coefficient becomes a shift. Scope narrowed accordingly.
As built: Kept, and measured: coefficient arithmetic is 50–56% of per-step cycles under the fast multiplier, with a roundoff/truncation crossover inside the practical step-size range (key finding 3).

Order ≥ 3 admits no all-dyadic tableauheld up

Original: Dyadic rationals are closed under + and ×; Σ b·c² = 1/3 is not dyadic. The objective is minimising non-dyadic multiplies subject to order, encoded as reject code DYADIC_IMPOSSIBLE so the search never wastes a cycle on an empty region.
As built: Kept, and it shaped the search space itself: A is snapped to dyadics but b is solved exactly over the rationals from the b-linear order conditions, because snapping b would run into this very theorem. The verifier rejects all-dyadic order-3 claims without evaluating them (tests V5–V7).

Static cycle counting, not simulation, not hardwareheld up

Original: The inner loop is branchless straight-line code, so summing ISA cycle costs gives an exact count and a genuine WCET figure; host contention cannot corrupt the metric.
As built: Kept, sharpened: the count is fully analytic from the tableau (no compiler or disassembly in the loop). The model is anchored to hardware by one hand-counted ARMv6-M sequence (13 cycles fast / 75 slow) that a test reproduces exactly, and emit_c exists for a one-time human cross-check.

Cortex-M0+ primary; AVR advisory; two M0+ multiplier variantsheld up

Original: M0+ has no FPU/divide/long-multiply, so fixed point is forced; running a 1-cycle and a 32-cycle multiplier model costs nothing and turns hardware-aware into a demonstrated effect if the ranking changes.
As built: Kept; the ranking does change (rk4 33 vs rk38 36 fast; rk38 64 vs rk4 85 slow; the anchor result on the overview). AVR stays advisory in a stronger sense than planned: after a live candidate was rejected on an AVR-column infinity, verification was restricted to primary-model columns only; the slow/AVR numbers are archive breadth.

Q15, wrapping semantics, overflow as a rejectionheld up

Original: Q31 must be synthesized on M0+; saturation costs a compare-and-branch and destroys exact counting. Overflow at 2× amplitude is a verifier rejection: a property of the method, not a runtime cost.
As built: Kept, with one addition the spec missed: rc_thermal's derivative (−11 at t=0) times its state scale exceeds Q15, so derivatives carry a per-problem power-of-two scale (DERIV_SCALE, 1/8 there) undone in the step via h. Floor rounding turned out to be a first-class experimental variable (key finding 2).

Classical optimizer in the inner loop, LLM in the outer loopheld up

Original: A 6-parameter space has gradients; CMA-ES beats an LLM mutation operator for free. The LLM decides what to search and interprets what came back.
As built: Kept, and the boundary held under pressure: when order-4 islands yielded nothing (exact order-4 b rarely solvable over dyadic A), the fix was a projection fallback in the optimizer, not more LLM. The outer loop grew: directives every N cycles with reuse between, a plan-usage cap, model-proposed hypotheses, and a web literature loop feeding every prompt.

Search/held-out split, enforced structurallyheld up

Original: The optimizer has no code path that reads HELDOUT_SET; the held-out gap is a first-class dashboard metric so it cannot rot unnoticed.
As built: Kept literally: a test walks the optimizer's import graph and fails on any load of the name. The D5 drill deliberately feeds the optimizer the held-out set, watches the gap collapse to zero, and restores it on revert, so the metric measures what it claims to. The gap is also an honest caveat on the champion numbers (key finding 1).

MAP-Elites, one grid per orderheld up

Original: Descriptors are stage count and cycle-cost bucket; a table of results rather than a single champion.
As built: Kept unchanged; the grids are the spine of the findings site (heatmaps + tables), and cell incumbency is what tier assignment compares against.

Equal cycle budget, never equal step sizeheld up

Original: A 2-stage method gets twice the steps of a 4-stage method for the same cost; equal-h comparisons are the most common route to a wrong conclusion.
As built: Kept, and it is the frame for every result on the key findings page: the rank flips and the efficiency frontier only exist at equal budget.

Fixed resource limits plus a pause watchdogheld up

Original: Low cpu-shares plus docker pause on contention stays out of the way in ~40 lines; no dynamic allocation, no GPU.
As built: Kept, grown modestly: the watchdog also pauses on battery (owner's rule), hard-stops on spend/disk, kills on a stale heartbeat, and pushes the two writable repos from the host. Thresholds live in config.json rather than in code.

Credentials outside the container; harness mounted read-onlyrevised in build

Original: If the agent can write the verifier, the shortest path to a high score is editing the scorer. PAT scoped to rk-work and rk-findings; the 403 on rk-harness is an acceptance test.
As built: Half-kept, half-superseded. The read-only mount and pinned verifier hash stand. The PAT scoping did not survive contact: the owner's token had contents-write everywhere, and the handoff's 403 probe passed for the wrong reason (missing Administration permission). As built, the credential simply never enters the container: a filtered env file plus host-side pushes, which makes the guarantee independent of token scope. The scope probe is kept as an advisory check.

Auto-publish numbers, never claimsrevised in build

Original: The site emits values with mechanically-assigned tiers; a wrong result should be a wrong number in a table, not a claim requiring retraction.
As built: Amended by the owner, with the guard intact: the findings site now also publishes model-written interpretation and web-researched literature digests, clearly labelled and passed through a softener that replaces priority-claim words before storage. The banned-words guard still hard-fails any page it doesn't like, and it proved itself by blocking builds over a hypothesis containing 'beats' until the softener existed.

The encourager may change direction but not stopheld up

Original: Before the calendar date it can only redirect, widen, hypothesize, or advance phase; set-and-forget systems without a calendar run until the operator gets bored.
As built: Kept: PACKAGE (re-verify everything, no new directions) opens 2026-11-20 and FREEZE 2026-12-05, property-tested over a thousand random states and exercised through the real clock path.

Falsification experiment firstheld up

Original: If coefficient arithmetic is swamped by derivative evaluation the thesis is dead; find out in week one, not month three.
As built: Kept, run, recorded either-way as promised: proceed for rk4 on both counts; heun2 under the slow model sits at 14.8%, a hair under the 15% line, so the verdict is stored as 'mixed' rather than rounded up (key finding 3).

What was deliberately cut

Adaptive step size and Newton-iteration implicit methods break the execution-time certificate hard real-time requires; wrong for the target, not merely unaffordable. Order > 4 and linear multistep multiply the space with no reason to expect a larger quantisation effect. Rosenbrock methods remain the natural second project. One addition to the cut list from the build: alternative rounding modes (round-to-nearest, stochastic rounding) are deliberately a measured comparison on the key findings page, not a search dimension, because changing the arithmetic changes every score in the archive, so it is pinned by the verifier hash.

Known prior art, and where the gap is

RKTK (Zhang, 2019) already performs unstructured numerical search over Butcher order conditions and holds an order-10 stage-count record; numerical tableau search is not the contribution. That line optimises order, stages and error constants in exact arithmetic. Nobody prices coefficients against a hardware cost model, and nobody evaluates end-to-end in fixed point; that is the gap, and it is narrow enough to finish. The literature loop keeps collecting adjacent work (fixed-point ODE solvers, CSD constant multiplication, rounding-error analysis) into the findings site's literature page as the run proceeds.

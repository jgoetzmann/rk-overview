Trust boundaries

The design assumes the searching agent will, if permitted, optimise the scorer instead of the score. Four boundaries make that unprofitable:

  • The scorer cannot be edited. rk-harness is mounted read-only into the container, and the container refuses to start unless the sha256 over the ten verifier files (coeffrep, orderconditions, verifier, costmodel, evaluator, problems, and the four fixture files) matches a pinned value. Every archive record carries the verifier hash that scored it.
  • No credential reaches the agent. The GitHub token stays on the host: the container receives a filtered environment, only ever commits into the mounted checkouts, and the host watchdog pushes with the owner's own credentials.
  • The model never grades itself. Confidence tiers (heldout_verified / search_only / unreplicated) and hypothesis verdicts (supported / refuted / inconclusive) are computed by code from the archive. The tier strings do not appear in any LLM prompt template; a directive carrying an unknown key — including a tier — is rejected, not ignored.
  • Model-written code is quarantined. A model-authored problem executes only after an AST-checked import allowlist (math only, no dunders, no I/O), determinism and time bounds, a range check, a reference solution, and a promotion gate; it can then join only the held-out set, so the optimiser can never be steered toward a problem the model invented.

The cycle loop

The runner executes one idempotent cycle at a time; a crash at any point costs at most one cycle because the archive is append-only with fsync, state is written atomically, and replay discards a torn trailing line. Each cycle: replay the archive → ask the encourager for an action → produce candidates → verify each → evaluate in Q15 under three cost models at equal cycle budget → assign a tier against the cell's incumbent → append → resolve open hypotheses → regenerate the findings site → commit → save state.

Verification, in order

Nine checks, cheap before expensive, all pure code: NOT_EXPLICIT, ROW_SUM_INCONSISTENT, DYADIC_IMPOSSIBLE (order ≥ 3 with all-dyadic coefficients is provably empty — the order-3 condition sums to 1/3, which no dyadic rational equals), ORDER_NOT_MET (exact rational residuals over rooted trees, never floats), COEFF_UNREPRESENTABLE (a range check — inexactness like 1/3 is recorded, never rejected), Q15_OVERFLOW (2× amplitude margin), UNSTABLE, NO_ASYMPTOTIC_WINDOW (the measured-order fit found no consistent slope run), NAN_OR_INF. Only the primary cost model's columns gate verification; the slow and AVR columns are archive breadth.

Arithmetic, exactly

States are Q15 (int16, scale 2-15). A multiply is (a*b) >> 15 with an arithmetic shift — flooring toward negative infinity, matching ASRS and deliberately not matching C's truncation. Addition overflow raises rather than wraps, so overflow becomes a verifier rejection instead of a silent wrong answer. Coefficients are not Q15: each is an integer-and-shift pair m/2s (rk4's 1 and kutta3's 2 do not fit [-1, 1)), and inexact representations contribute a recorded quantisation error. Cost is driven by CSD (non-adjacent-form) weight — 3/8 is dyadic yet costs two shifts and an add — with every coefficient priced at min(shift-add expansion, multiply).

Where candidates come from

Phase 0 and 1 are exhaustive enumerations (16 points at order 2; 5,094 exact 3-stage order-3 points), so their results are proofs of optimality within the enumerated space, and the site labels them that way. Phases 2 and 3 run CMA-ES islands over the strictly-lower triangle of A snapped to dyadics, with b then solved exactly over the rationals from the b-linear order conditions — snapping b would make order ≥ 3 impossible by the dyadic theorem. When the requested order is not exactly solvable for a snapped A (order 4 rarely is), the projection falls back to the highest solvable order ≥ 2 and the candidate is verified at the order it actually achieves.

The outer loop: a research partner, not a sampler

The LLM (Codex, plan-billed, authenticated on the host and mounted read-only) never touches the inner loop. It emits JSON directives that can only narrow the search — target order, stage counts, structural constraints — validated against a schema where unknown keys are rejections. Directives are requested every few cycles (and on every escalation) and reused in between; calls stop at a plan-usage cap. On HYPOTHESIZE escalations it proposes falsifiable hypotheses whose ids and verdicts are assigned by code and whose predicates must parse under a closed grammar (a hand-written parser; no eval anywhere near model output). A literature loop web-searches a rotating topic every ~50 cycles and feeds the digest into every prompt, so the directives and hypotheses are grounded in existing research. The digests and the model's prose interpretation are published on the findings site, clearly labelled and softened so the site's banned-words guard holds.

The host layer

A PowerShell watchdog polls every 10 s: stale heartbeat → kill; spend over cap or disk under 5 GB → stop; laptop on battery or foreground CPU load → pause (and resume); plus the host-side pushes. Operational knobs — container resources, auto-stop after N minutes/cycles, LLM throttles, watchdog thresholds — live in a workspace config.json edited by configure.py; scientific thresholds are deliberately not configurable because changing them invalidates the archive. A read-only watcher window renders the whole state live; Ctrl+C in it cannot touch the run.

What the pre-flight actually caught

The checklist was executed as a program, not a document, and it earned its keep: the crash -recovery drill exposed that a runner killed mid-seeding never finished writing the classical baselines (fixed: seeding is idempotent per hash, every cycle); the trust-boundary probe showed the original PAT could push the verifier repo despite the handoff's 403 test passing (fixed by moving the credential out of the container entirely); the first live archive build tripped the banned-words guard on a hypothesis containing “beats” — the guard doing exactly its job against text nobody reviewed.
